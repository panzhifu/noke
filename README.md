# noke · 个人网站

打开网站先看见的**不是房间,是一扇关着的门** —— 点它,门推开、镜头走进去,家具才显形。
之后才轮到那间房间:没有滚动、没有导航条、没有可见文字,家具可以点,
点开的五格面板在桌面端是右上角的卡片、窄屏退回底部抽屉。

Rust + [Leptos](https://leptos.dev)(CSR,编译成 WebAssembly)负责界面与状态,
房间由 [Three.js](https://threejs.org) 渲染,家具模型在 Blender 里做、导出成 glb。
Trunk 构建,托管在 GitHub Pages。纯静态:没有后端、没有 Cookie、没有第三方追踪;
Three.js 随仓库一起发布,运行时不从 CDN 拉任何东西。

线上地址:https://panzhifu.github.io/noke/

## 当前状态

| 已经进 3D | 点了会开面板 |
| --- | --- |
| 地毯(铺在书桌下)、书桌、桌上的显示器 + 机械键盘 + 鼠标 + 一盏剪式臂台灯、**一台小便携唱机(盖子能开合、唱盘会转)**、**塞在桌下右格的那台侧透机箱**、床、冰箱、电竞椅、床尾立着一把**带支架的电吉他**、背墙上嵌着一扇**能推开的门**、门旁边挂着一张**当封面的黑胶**,外加一间「墙角 + 地板」的舞台 —— 见 `src/room/manifest.rs` | 书桌、显示器和键盘(都开「作品」)、床(开「关于」) |

**两扇门可以点开**:冰箱那台 glb 里门是一个独立节点,绕竖直铰链(前右竖边)开到底 89.888°——
这两个数不是估的,是从 `~/blender/fridge.blend` 自带的「开门 → 关门」骨骼动画里反解出来的
(见 `target/tmp/export_fridge_door.py`)。背墙上那扇是本地建模的(`~/blender/门.blend`,门扇 + 门框 +
三副合页 + 双面把手),源文件摆的就是开着 90°,按同一条约定烘成**关着**的、清单里给 +90 转出去,
往墙后那段暗腔里开。所以清单里 `door` 给的是 `{节点, 轴, 角度}` 三件套,不是「一个节点名 + 一个全局角度」。

**唱机有三样会动**:点一下防尘盖**掀开 / 合上**(绕水平的 z 转 32.077°);房间灯开着的时候
**唱盘自己转**,33⅓ 转/分(一圈 1.8 秒),灯一关就停 —— 这个循环是**按需渲染**的,唱盘常转就等于
帧循环永不停摆,所以「什么时候转」挂在房间灯这枚现成的开关上(见 `assets/room/main.js` 的
`stepPlatter`)。那张 AC/DC 黑胶**不再躺在唱盘上了**,改成挂在背墙上当封面 —— 一半是构图
(那台小机器只吃 7 寸盘,12 寸的盘得缩到 0.55 才配得上,缩完就不像一张真的唱片),
一半是盖子合下来的时候盘子得让路。

**电竞椅点一下转一圈**:转的只有**上半身**(座椅 + 椅背 + 扶手,glb 里的 `chair_upper` 节点),
360° 缓出停下(和冰箱门同一套缓出手感),连点会排队、最多排三圈,`data-spin`(`spinning` / `idle`)
与 `data-turns`(累计圈数)写在 `#room3d` 上供核对。五个轮子和气压杆在另一个节点 `chair_base` 里、
原地不动 —— 整椅一起转的话轮子会贴着地面画圈,那是个假动作。它进 `pickables` —— 代价是**椅背正后方那一小块桌面点不动了**
(书桌左右两侧照常开「作品」),这是明确选过的取舍:看得见的是椅子,点中椅子更合直觉。
电竞椅和那台侧透机箱都是 Sketchfab 上的模型(Man1ac 与 Daniel Cardona),**CC-BY-4.0**,
署名放在「关于」那格(`src/content.rs`)。机箱是纯装饰、不进 `pickables`(一个 glb 里 85 个
材质分组,挂上 `spot` 就是 85 次真实几何求交 —— 见「踩过的坑」)。

这两件事对模型的要求不是包围盒能看出来的,都在清单字段的注释里写清了:门要**独立节点 + 原点在铰链上**,
转椅要**上半身单独成节点 + 它的原点在旋转轴(底盘立柱)上**。电竞椅这两条都是导出时一次做完的:
按**蒙皮权重**把 `seatBase` 那一支(座椅 + 椅背 + 扶手 + 调节手柄)切成 `chair_upper`、其余切成
`chair_base`,两半再共用同一套归一化 —— 水平按底盘轴心(骨架里 `wheelBase_10` 那根骨头)居中、脚底贴地、
收到 1.26 m 高,所以两个节点的原点都正好在那根竖轴上。脚本 `target/tmp/gaming_chair/split_spin.py`,见「踩过的坑」。

剩下三格(手记 / 联系 / 海报)靠面板头部的左右箭头到达;键盘 Tab 则从 `sr-only` 的入口条进。
页面上没有可见文字,所以**没有「搬完家具就删掉的临时按钮」这回事了** —— 入口条是长期给键盘和读屏留的通道。

## 首屏是门:门厅、推门而入、以及加载

3D 层是一个阶段状态机,`<html data-phase>` 就是它的对外接口
(`assets/room/gate.js` 只写这一个属性,谁该露出来全在 CSS 里判):

| 阶段 | 画面上有什么 | 什么时候到这里 |
| --- | --- | --- |
| (空) | 加载界面:一扇正在打开的门 + 一条进度轨 | 下载 `door.glb` |
| `porch` | **门厅**:那扇关着的门,门前一小段地板与墙 | 门到了(首屏到此为止,其余家具在后台补) |
| `walking` | 门开、镜头推到门口、一块幕把换景盖住、退到定位镜头 | 点门(或入口条上那枚「推门而入」) |
| `room` | 整间屋子,顶栏两枚开关此时才可用 | 走位走完 |
| `page` | 纯 DOM:入口条能用,3D 这层没有 | WebGL 拿不到 / 一件家具都没加载上 / 15 s 超时 |

**加载分两档,是为了首屏。** 全套 glb 是 12 MB,而门只要 428 KB —— 所以门先到、先画,
剩下 11.6 MB 在门厅这段时间里以 4 路并发补齐(`models.js` 的 `loadAll`,原先是一串 `await`
挨个下,一个请求一轮往返)。新到的一律 `visible = false`:装进场景但先不画,所以
`Box3.setFromObject` 照样量得到(它不看 `visible`),取景与包围盒的口径一点没变。

**预热排在「能进」之前**:家具齐了之后在空闲期(`requestIdleCallback`)把每件材质的着色器
`compile` 一遍、每张贴图 `initTexture` 传上去,做完才允许进门。不然那一拍是「显形十几万面 +
编译十几套材质 + 上传几十张贴图」挤在同一帧里。提前编译能成立是因为
`WebGLRenderer.compile` 走的是 `traverse` 而不是 `traverseVisible` —— 藏着的家具也编得进来;
贴图就不行了,它要真被画到才上传,所以得逐个点名。

**门厅那一格是同一场景里摆出来的,不是另起一个渲染器**:景片(地板 + 带门洞的墙 + 暗腔)
按门自己的包围盒铺一份,家具那份等量完真包围盒再建,建好先藏着,换的时候由那块幕盖住。
镜头距离是从门的尺寸算的(`porchPose` 按垂直角与水平角各算一次取远的那个),
所以换一扇门、改一下缩放,构图自己跟上。雾在近处收住,门框以外化进背景。
`spanMeters` / `centerMeters` 与不进门时完全一致(`[4.68, 1.34, 3.4]` / `[-0.38, 0.67, -0.41]`)。

**「推门而入」是两段,不是一镜到底**:门在背墙上,而房间在门的同一侧,门后只有 1.2 m 深、
还被开着的门扇占住的暗腔 —— 穿不过去。所以走法是「推到门口(画面被暗腔填满)→ 幕全黑那一帧
换景 → 从屋里往外退到定位镜头」,补间在 `porch.js`,时长 1.9 s,`ENTER_REVEAL` 是那一帧的位置。
减弱动效(`prefers-reduced-motion`)时整段跳过,直接落位。

## 光照的四个状态

顶栏是两枚药丸开关:**房间灯**(书桌上那盏台灯)与**昼夜**(就是站点的深浅色主题)。
两维相乘即四态,颜色与强度全在 `assets/room/palette.js` 一张表里:

| | 灯关 | 灯开 |
| --- | --- | --- |
| 白天 | 天光为主,暖白、影子硬 | 灯罩亮起,灯下多一圈暖光 |
| 夜里 | 冷月光,低照度 | 环境压到最低,只留灯下那团暖光 |

状态切换是**渐变**不是硬切:3D 层每帧把颜色与强度往目标态插(缓出曲线),`toneMappingExposure`
也一起插;插值没走完时按需渲染的循环不许停摆,否则画面会定在渐变半路。

**「房间灯」那盏聚光挂在灯泡上**:台灯是清单里的一个 glb(`assets/models/desk_lamp.glb`),
开灯时的自发光与 SpotLight 的位置都从模型里**按材质名认出灯泡那颗球**来定
(见 `config.js` 的 `LAMP_BULB_MATERIAL` 与 `scene.js` 的 `findLampBulb`),灯头在几厘米高
是导出与摆放定死的事,网页里再手算一遍就是一份会过期的坐标。光放在灯泡底缘往下 2cm,
不放球心 —— 罩子扣在灯泡上,光得能从罩口漏到桌面上。

做法参考了 [pinchen.me](https://pinchen.me/) 那间房(它顶栏也是这两枚开关、四态也是这么分的)。
它那边光照是**烘焙进贴图**的(每态一整套 webp),这边全靠实时灯 —— 表里的 lamp 强度因此给得比它重。

## 镜头:定位、拉近、放回

整间屋子的定位镜头是 `framing.js` 从家具包围盒倒推的:俯角 16°、方位角 30° 定死,
距离按包围盒在相机三轴上的投影取最坏那一档(`CAMERA_FILL = 0.8`)。往左右转、推拉,
都在 `config.js` 的钳位里:`POLAR_LIMITS [48,88]`、`AZIMUTH_LIMITS [0,62]`、
`DISTANCE_RANGE [0.55,1.9] ×` 定位距离。

**点中一件会开面板的家具(书桌 / 显示器 / 键盘 / 床)顺带拉近**:`focusOn` 把注视点挪到
那件东西上,再写一个「目标半径」交给 `loop.js` 逐帧推过去 —— 只改「注视点 → 镜头」这段
长度,方向不动,所以用户已经转到的角度留着。半径是 `fitDistance`(和门厅量门同一条式子)
按**这件东西自己的包围盒**算的:点床只凑近一点,点键盘会贴得很近,不会出现「什么都是
同一个缩放倍数」。

两个收口:

- 上限是定位距离、下限是 `DISTANCE_RANGE[0] ×` 定位距离(滚轮本来就推得到的最近处)。
  有了这条下限就不必临时放宽 OrbitControls 的钳位 —— 放宽了就得记得改回来,那笔账最容易漏
- 谁动这个半径谁负责收:`Esc` / 面板上的 × 走 `releaseFocus`,镜头放回定位那一格;
  滚轮一动说明用户自己在缩放,那次拉近的目标当场作废(否则两边抢同一个数);
  resize 之后旧的拉近目标已经没有意义,`refit` 一并清掉

减弱动效(`prefers-reduced-motion`)时这一推是直接落位,不走缓出。

## 加一个模型

四步:

1. **Blender 里做**,先导出一个原始 glb(贴图会一并嵌进去)。
   导出前删掉灯光 —— 网页自己打光;粒子系统也去掉,glTF 不支持、导出器会报错。
2. **过一遍 `tools/compress_glb.py`**(无头 Blender,不需要开界面):

   ```bash
   blender --background --python tools/compress_glb.py -- \
     原始.glb assets/models/名字.glb 15000 1024
   ```

   它把层级 join 成一个网格、降面、贴图封顶后转 WebP,再归一化成「米、脚底贴 z=0、水平居中」,
   最后打印一段 JSON(尺寸、包围盒、面数)—— 照着它填清单里的 `position` / `scale`。
   已经在清单里摆好的模型加 `keep`(只降面和压贴图,不碰方向单位);
   高度是最长边的家具(冰箱这类)加 `no-up`,否则「最薄的一面当顶」会把它放倒。
   再往后三个都可选:WebP 质量、**单位换算**、几何压缩 —— 目标面数写 `0` 是「一点都不降」,
   单位那一格直接写「源模型一个单位等于多少米」(Sketchfab 有一批包是**英寸**导出的,
   见下),压缩写 `none | draco | meshopt`。跑完打印的 JSON 里带 `outputCheck`,
   它回头读自己写出的 glb,能当场看出贴图有没有丢。
3. **在 `src/room/manifest.rs` 的 `MODELS` 里加一条**:路径、位置、旋转、缩放,以及三个可选的
   交互字段 —— `spot`(点了开哪格面板)、`door`(可开关的部件:节点名 + 绕哪根轴 + 开到底多少度)、
   `spin`(glb 里那个要转的节点名)。嵌在墙上的东西(门)还要写 `wall: true`。
4. 给了 `spot` / `door` / `spin` 就到此为止 —— 家具自己就能点了。`EntryBar` 是键盘/读屏通道,不用跟着改。

### 贴图质量:先保证材质,再谈体积

`compress_glb.py` 第 6 个参数是 WebP 质量(默认 70)。**深色 / 靠贴图讲细节的家具要给到 95**
——低质量下丢的正是「材质看得出是什么」的那点信息。办公椅就是照这个来的:

```bash
blender --background --python tools/compress_glb.py -- \
  ~/Downloads/office_chair.glb assets/models/office_chair.glb 12000 1024 no-up 95
```

| 质量 | 体积 | baseColor PSNR | normal PSNR |
| --- | --- | --- | --- |
| 88 | 1.26 MB | 41~53 dB | 31~52 dB |
| **95** | **2.22 MB** | **47~52 dB** | **35~43 dB** |
| 原图字节不动 | 9.29 MB | ∞ | ∞ |

量到什么程度就够了:**在同一机位下把两个版本分别渲出来比像素**,办公椅 88 与 100 的差
只有 1.26/255(超过 8 灰阶的像素 46 个 / 8.7 万),肉眼不可辨 —— 所以要更细的调整就别再往
质量上加了,去看材质本身与打光(见下)。真要字节级无损,把第 6 个参数写成 100 即可,
导出脚本 `target/tmp/chair/export_faithful.py` 是「只归一化、贴图一个字节都不动」的那一档。

### 显示器那块屏:桌面截图当贴图

`computer.glb` 里屏幕是一个单独成组的面(`material 3`,8 个三角形),整面 UV 就是 0~1,
所以「屏幕上是什么」完全由那张贴图决定 —— 换桌面不用碰模型,只换图:

```bash
python3 tools/replace_screen.py ~/桌面截图.png        # 直接写回 assets/models/computer.glb
```

它按屏幕那面的**物理宽高比 1.615**(量自模型里那个面的包围盒:x 占 109.13、y 占 67.56)
居中裁一刀、缩到 1024 宽、转 WebP q92,再重写 GLB —— 只换 `images[0]` 那份字节,
其余 bufferView 原样搬过去并按 4 字节对齐重排,所以旧的图不会留在文件里占地方。

居中裁是刻意的:上下各切掉一条,菜单栏和任务栏都留着 —— 那两条正是「这是一张桌面」的记号。
原先那张是 512×256(2:1),被这张 16:10 的面拉得有点走形,现在按真实比例给。

### 几何重的东西交给 Draco

降面是最钝的一把刀:**皱褶、布料这类「形状本身就是内容」的模型,一降就糊**。
床的褥子 + 枕头 + 床单原本是 30.7 万面,老版本按 2.5 万面压 —— 于是网站上那张床
和原模型差了十万八千里。正解不是继续降面,而是**几何单独压缩**:

```bash
blender --background --python tools/compress_glb.py -- \
  ~/Downloads/dream_computer_setup.glb assets/models/pc_tower.glb 0 1024 no-up 95 0.0254 draco
#  第 3 个参数 0 = 一点都不降面;第 7 个是单位换算;最后一档 none | meshopt | draco
#  床那台是先例(当时走的是 target/tmp/bed/export_bed.py,同样的参数组合)
```

| 方案 | 几何 | 贴图(1024²,WebP 95) | 合计 | 面数 |
| --- | --- | --- | --- | --- |
| 床:降面到 2.5 万(旧) | 0.64 MB | 0.15 MB | 0.8 MB | 2.5 万 |
| 床:meshopt(无量化) | 8.27 MB | 1.25 MB | 9.5 MB | 30.7 万 |
| **床:Draco** | **0.81 MB** | **1.25 MB** | **2.07 MB** | **30.7 万** |
| **机箱:Draco** | **1.28 MB** | **1.01 MB** | **2.36 MB** | **21.16 万** |

机箱是这条路线最划算的一个:源文件 15.7 MB,一台 21.16 万面的玻璃侧透主机(主板上的
电容、针脚、水冷接头各是各的形状),降面降不得 —— 降到 2.5 万面那团元件就糊成一锅。
按上面那行跑完是 2.36 MB,同一机位与源文件逐像素比:**PSNR 36~53 dB、平均差 0.36/255**,
超过 8 灰阶的像素占 1%,肉眼分不出。

**单位那一格为什么必填**:这台是 Sketchfab 上的 Maya 包,单位是**英寸** —— 整包最大边
19.59,`compress_glb.py` 那条「最大边 > 30 就按厘米」的启发式会把它当成 19.59 **米**。
写 `0.0254` 之后落到 0.452 宽 × 0.498 高 × 0.267 厚,正好是一个正常中塔;
判据不是猜的,是量了机箱风扇(3.53 单位 = 92 mm 标准风扇)和主板(12 × 9 英寸)对出来的。
显示器那台 3ds Max 包同理,单位既不是米也不是厘米,只能写在清单的 `scale` 里。

`meshopt` 在 Blender 里不做量化,单靠它省不了多少;Draco 带位置/法线/UV 量化,几何掉到 1/10。
代价是要带解码器:`assets/vendor/addons/loaders/DRACOLoader.js` +
`assets/vendor/addons/libs/draco/gltf/{draco_wasm_wrapper.js, draco_decoder.wasm, draco_decoder.js}`
(约 760 KB,wasm 优先、js 兜底),`assets/room/models.js` 里一行 `setDecoderPath` 指向它。
**没有 Draco 的模型照常加载**,解码器只在真碰到 Draco 网格时才去取 —— 所以这一档可以只给需要的家具用。

### 坐标系以 Blender 为准

导出时 Blender 已经把 Z-up 转成 glTF 的 Y-up,所以**模型在 Blender 里摆在哪、清单里照抄就行**,
不用做单位换算。地毯平铺在 XZ 平面、y = 0。

`position` / `rotation` / `scale` 对应 three.js 的 `Object3D`;`rotation` 写**角度**,JS 那边负责转弧度。

`spot` 的取值要和 `panel::Spot` 对得上:`"work"` `"about"` `"notes"` `"contact"` `"poster:0"`。
写 `None` 就是纯装饰、点不开。

`door` 与 `spin` 是另外两种「点了会动」,给的都是 glb 里的节点 —— 但**两者的信息量不一样**:
`spin` 只要一个节点名(电竞椅的 `chair_upper`,原点落在底盘立柱上),转一圈就是转一圈;
`door` 要给 `{node, axis, deg}`,因为门的几何比这杂:冰箱门绕**竖直**的 y 转 89.888°,
现在这台唱机的防尘盖绕**水平**的 z 转 32.077°,而上一台唱机的盖子绕**水平**的 x 转 -85.552°
(负号 = glb 里烘的是「关着」的姿态,点一下是转出去;这台唱机也是烘关着的,但它的合页与
盖子的倾斜方向凑出来是正数)。
早先这里是「`door` 也只给节点名 + 一个全局 `DOOR_OPEN_DEG` + 写死 `rotation.y`」——
第二扇门一接上就必有一件是错的。`config.js` 现在只留手感(`DOOR_EASE` / `SPIN_DEG` / `SPIN_EASE`)。
两者都写了也不会互相打架 —— `door` 优先。给了这三个字段里的任何一个,家具就进 `pickables`,会参与拾取。

### 尺度不用手调

相机距离、阴影范围、地板大小都是**按场景实际的包围盒算的**(`fitRig` / `fitCamera`),
所以把地毯换尺寸、或者往房间里添别的东西,构图会自动跟上。

**墙上嵌的东西要写 `wall: true`** —— 它得**排除**在这次测量之外。背墙的位置就是从这个包围盒
推出来的(`center.z - size.z / 2 - WALL_PAD`),门要是一起算进去,盒子被撑大、墙就被自己推远,
而这个反馈**没有不动点**(墙退 0.9,门就得再往后贴 0.9)。表现是「加一扇门,整间屋子拉远一圈,
门还悬在墙前面」。`fitRig` 会先把这类节点摘出去量完再装回来;贴墙那一步在 `main.js` 里,
等 `createWalls` 定了 `backZ` 才做,所以门永远跟着墙走(墙以后挪了也不会脱开)。

### 踩过的坑

- **importmap 的位置**:Trunk 把 wasm 加载脚本注入到 `<link data-trunk="rust">` 那一行的位置,
  而 importmap 只要晚于任何 module 脚本出现就会被浏览器忽略,`import 'three'` 会全部解析失败。
  所以 importmap 写在了那行上面 —— 别往下挪。
- **three r186 拆包**:`three.module.min.js` 里写死 `import "./three.core.js"`,
  所以下载 `three.core.min.js` 后要**存成 `three.core.js`**,文件名不能改。
- **`PCFSoftShadowMap` 在 r186 被移除**,改用 `PCFShadowMap`(否则每次启动都有一条 warning)。
- **`--public-url` 必须带**:不带的话 Trunk 生成的是根路径资源,子目录部署直接 404。
- **body 的三行 grid**:`.room3d` 是 `fixed` 的、不占 grid 行,页脚会顺着往上跑一格。
  现在 `body:has(> .room3d)` 把它改成四行(顶栏 / 入口条 / 场景 / 页脚)。
- **画布收不到拖拽 = 层叠顺序,不是 OrbitControls**:`.room3d` 的 `z-index` 一旦是负数,
  CSS 绘制顺序里它排在 in-flow 的 `body` 盒子之前,命中测试按反序走 —— `body` 成了挡在画布
  上面的那一层,`pointerdown` 一个都到不了 `OrbitControls`(换控制实现也治不好)。
  同理,页面上任何一个 `z-index:2` 的透明盒子摊开铺满视口,房间中间也就拖不动了
  (顶栏因此要 `align-self: start`,别让 grid 的 stretch 把它拉成满屏)。
  核对方法:`document.elementFromPoint(房间中央)` 应当返回 `CANVAS`。
- 🔴 **贴着地面的东西必须和地板同组**:视差的俯仰是 `rig.rotation.x` 绕原点转整组,
  幅度约 ±1°。只离地 2mm 的地毯要是在场景根上、地板在组里(或反过来),转过一侧
  就会被地板整条盖掉 —— 表现是「转动视角时地毯缺一块」。现在地板 `rig.add(floor)`、
  模型也都在 rig 里,没有相对位移;地毯自己再抬到 4mm 当绒高,双保险。
- **取景靠 `fitCamera`,尺寸变化不用手调**:相机距离、雾的近远端、阴影相机范围都是按
  场景包围盒算的。删掉电动车、把地毯从 3.48m 收到 2.53m 之后,构图自己跟着收紧了。
- 🔴 **取景必须按方位角投影包围盒**。`fitCamera` 早先只拿 `size.x` 当画面宽度,等于假设
  镜头正对场景;初始方位角一给到 30°,场景在画面上的投影宽度就涨到接近对角线,
  近的那件家具(床)直接被切在画框外。现在把包围盒投到相机自己的 right/up/前向三个轴上算,
  并且**固定用初始方位角那 30°** ——包围盒 4.76 宽 × 3.4 深时投影宽度恰好在 30°~40° 最大,
  拿这个「最坏角度」定距离,整段方位角范围内都不会被切,resize 也不会改构图。
- 🔴 **光照渐变没走完时,按需渲染的循环不许停摆**。`loop.js` 靠「连续 6 帧画面签名不变」
  判定可以停 rAF;而光照插值不改镜头也不改 `rig.rotation`,签名自然不变 ——
  中间几版就是插到一半画面定住。现在给循环加了个 `step(dt)` 钩子,它返回 true 时 `quiet` 归零,
  同时把 `toneMappingExposure` 加进签名。
- **墙角是两块「景片」,不是一间封闭的屋子**:高度要够到「俯角 16° 时上边缘出画」
  (现在 5.6m,给拉远留了余量),否则画面顶上会露出背景;宽 2.6×跨度。它们和地板一样
  必须挂在视差组里,否则俯仰一转,墙脚与地板之间会裂出缝。
- 🔴 **会动的部件要单独成一个节点,原点落在铰链上**。冰箱门就是这么导的(见
  `target/tmp/export_fridge_door.py`):把门从箱体里留出来、其余 join 成 `fridge_body`,
  门的几何烘成「关着」的姿态、节点原点搬到铰链 —— 网页那边只要转它自己的 `rotation.y`。
  铰链与角度**从原件的动画里反解**(取开门帧与关门帧的相对变换 R,解 `(I - R)p = t` 得铰链点),
  别手算:写成 `R - I` 会把铰链解成它的相反数,差一个负号,门就绕着另一条边转。
- 🔴 **会转的要单独成一个节点,原点落在那根竖轴上** —— 转椅和冰箱门是同一条规矩(见
  `target/tmp/gaming_chair/split_spin.py`)。转的是 glb 里那个节点的 `rotation.y`,所以节点原点必须
  正好压在底盘立柱上,否则上半身是**绕着一根偏心的轴公转**;底座另成一个节点、原地不动。
  **别转根节点**:整椅一起转就是「连轮子一起拧」,一眼就是假的 —— 而根节点旋转是当初唯一能做的选择,
  代价也在这:清单里那句 `rotation: (0, 69.83, 0)` 和转圈累加在同一个 `rotation.y` 上,基准角得先存下来。
  **轴心能从骨架直接读**:导入后 `arm.matrix_world @ pose.bones['wheelBase_10'].head` 就是底盘立柱的位置
  (比拿网格猜可靠),归一化时按它水平居中即可 —— `tools/compress_glb.py` 默认的「包围盒中心」对办公椅
  恰好等于轴心(实测偏差 0.000 m),但对椅背往后伸的电竞椅会偏出 3cm。
- 🔴 **切「上半身」按蒙皮权重切,别按水平面切**。这台椅子的骨架已经把答案写好了:`seatBase` 那一支
  (座椅 + 椅背 + 两只扶手 + 调节手柄)就是会转的部分 —— join 完顶点组还在,按每个多边形两边的权重和
  分给谁就够了(实测 54,379 面里 49,104 归上半身、5,275 归底座,**零骑墙、零没蒙皮的**)。
  按高度切看着更省事,但**调节手柄有一半比气压杆顶盖还低**(切完底座最高 0.22 m、上半身最低 0.198 m),
  一刀水平面下去会把这几片从机构上撕下来;切完记得核对两半的接缝,以及导出的 glb 里节点名还在不在
  (网页那边是按名字取的)。
- 🔴 **带骨架的模型过压缩管线,要先扔掉「骨头的自定义显示形状」**。glTF 导入器会给每根骨头
  建一个半径 1 的球当 `custom_shape`(中文界面里叫「棱角球」),它是一个**普通的 MESH 对象、躺在场景里**。
  `compress_glb.py` 的 `scene_meshes()` 会把它一起 join 进模型、还被当成地面基准 —— 表现是模型里
  嵌了一个球、整件悬空一个球半径、归一化基准也全歪。没有骨架的模型(办公椅)不会出现这个对象,
  所以以前的家具从没撞上。判据:`o.type == "MESH" and o.name in scene.objects` 之外,
  再排掉所有 `pose.bones[*].custom_shape` 指向的那些。
- **蒙皮模型先把 armature modifier 烘掉再 join**:`join` 只保留 active 对象的 modifier,
  留着骨架的话后面 join 出来的东西会少一块变形。
- **朝向永远出图确认,顺便让骨架和出图互证**:转椅的正前方可以从骨头算(椅背骨头 → 座椅骨头
  的水平连线,取反),`gaming_chair` 算出 110.2°;再从几何算(最高 12cm 那一段的质心偏向哪)
  得 109.1°,两者差 1°。但清单里该写多少度,最后还是要按那个角度转出来渲一张才算数 ——
  包围盒在两个方向上都一样,看不出正反(办公椅当初就是这么定的)。**注意 Blender ↔ three 的
  旋转符号**:three 的 `rotation.y = +θ` 对应 Blender 绕 Z 转 **−θ**(`three z = −blender y`),
  差了符号就会把椅子转过去 140°、还以为「看起来差不多」。
- 🔴 **`tools/compress_glb.py` 修过两处,都是「模型出来不对」的根因**:
  ①解父链要用 `CLEAR_KEEP_TRANSFORM` 而不是 `CLEAR` —— glTF 导入时那层根节点的
  Y-up→Z-up 旋转也在父变换里,`CLEAR` 会连它一起丢掉,几何躺倒,后面的 `up_fix` 再盲目补
  +90°,两者一正一负就翻成 180°(唱机当初就是这么被压成倒扣的);
  ②保留变换会把根节点的缩放(常常是 ×100)带下来,而 `unit_scale` 是**赋值**不是**相乘**,
  不先烘焙一次的话 42.7cm 会再被缩 100 倍成 4mm。
- **算包围盒别读缓存**:`bound_box` 与 `matrix_world` 都是缓存,改完数据/位置不调
  `bpy.context.view_layer.update()` 读到的还是旧值 —— 冰箱门那次「水平居中」就是因此
  把已经摆好的门又挪了 33cm,门跑到箱体里去了。按顶点现算最稳。
- **台灯的强度不能照抄 pinchen 的数**:那边场景一单位≈这边 0.1 米,它的 `lamp: 24` 换到
  米制大概是 0.2~1.6 这个量级(聚光衰减是 `decay: 2`,照度按 1/d² 掉)。直接抄 24 的话
  桌面会被烧成一片白。
- 🔴 **面数一上来,拾取就成了瓶颈**:`Mesh.raycast` 是「先球/盒快筛,再逐三角形求交」——
  射线一旦命中就要走遍全部三角形。床换成 Draco 全几何(30.7 万面)之后,
  `intersectObjects` 实测 **20.6 ms / 次**,而这个拾取是**跟着帧**跑的一帧一次(见 `loop.js`:
  高刷屏上 pointermove 能到 1kHz,所以刻意按帧摊),鼠标停在床上就一直掉帧。
  现在 `models.js` 里给 ≥1 万面的网格换成**包围盒代理**(`useBoxPick`):射线与自己那块
  几何的局部包围盒求交,命中的 `object` 仍然报真网格,所以指针形状 / `data-hover` / `spot`
  全都不变 —— 同一发射线从 20.6 ms 掉到 **0.152 ms**。代价是盒子角落那点空档也算命中,
  对「一整张床」这种目标无所谓;像冰箱门(5082 面)这种要精确到拉手的,阈值以下不碰。
- 🔴 **包围盒代理那一档按「单个网格」算,所以分组多的模型躲不过去**。机箱 join 完是
  85 个材质分组 = 85 个 primitive、21.16 万面,可**每一块都不到 1 万面**,`useBoxPick`
  一块都不会接管 —— 给它挂 `spot` 就是每帧 85 次真实几何求交,加起来还是那 20 ms 级别。
  所以机箱的 `spot` 是 `None`:
  开「作品」交给书桌和显示器。**分组数多的模型,要么别做成可点,要么先在 Blender 里合并材质**。
- 🔴 **灰度贴图会让导出器写出一个「没有 source 的 texture」,浏览器整模型加载失败**。
  Blender 5.2 的 glTF 导出器要把内嵌贴图转 WebP 时,会 `image.copy()` 一份临时图再 `save()`
  (`encode_image.py` 的 `__encode_from_image`);源图是**灰度 PNG** 的那几份存不下来 ——
  日志里是「未能将图像 'Image_2.001' 保存至 /tmp/...」+「Image data is empty, not exporting
  image」,可导出**照样成功、退出码 0**,只是那几张 texture 成了空壳。表现是页面上一句
  `Cannot read properties of undefined (reading 'uri')`,`[room3d] 加载失败`,家具整个不见。
  机箱 24 张贴图里 3 张是灰度(主板芯片组、两条内存的 baseColor),全中。
  判据是 `img.depth == 8`(`img.channels` 对这类图仍报 4,不说真话),
  `compress_glb.py` 的 `to_rgb()` 会先把它们重建成 RGB 再导;
  跑完 RESULT 里的 `outputCheck.texturesWithoutSource` 是这道关的自检 —— **别只看退出码**。
- 🔴 **一块「不受光的暗面」还得同时关掉雾,否则它不暗**。门后那段暗腔用 `MeshBasicMaterial`
  (墙后没有灯,不该吃这间屋子的光),但腔底离镜头十来米、早过了雾的近端,被雾抹成三四成的背景色 ——
  材质系数从 0.12 一路调到 0.004,量出来都是 sRGB 95 上下那一坨灰。两层原因叠着:`THREE.Color` 存的
  是**线性**值(×0.12 折算到屏幕只等于 ×0.34),渲染器又挂着 ACES(暗部还有一层提升)。
  判据是**量像素**不是看图:洞里 (34,33,31) 对背景 (196,190,179) 才叫「里面没开灯」。
- 🔴 **合页不是「会动的那块最低的顶点」**。唱机防尘盖是带裙边的一块板,它的最低边垂在机身
  **后壁外侧**,比真合页低了 5 cm —— 拿那圈顶点当轴,盖子合下来整片扎进唱盘。真合页是
  **底座的后上棱** (y=0.1607 / z=0.0872)。冰箱那台的铰链是从 `.blend` 自带的开合动画反解的,
  这台没有动画,只能量 —— 而**判据很便宜**:把盖子转完的包围盒和唱盘顶面比一下,低了就是错的
  (`split_cover.py` 里那段 `CLOSED_COVER` 就是干这个的),别等出图才发现。
- 🔴 **`data-door` 不能按 `target > 0` 判断开没开**。glb 里烘的是「关着」的姿态(冰箱守这条约定),
  而上一台唱机的「掀开」是个**负**角度(源模型摆的是开着,导出时先转回闭合),
  按符号判断状态就整个报反。现在 `toggleDoor` 带一个显式的 `open` 标志 —— 和转椅那次
  「按 `angle === target` 收尾会永远停在 spinning」是同一类教训:**状态要用标志说,不要用几何量猜**。
